# Biztalk
	
##Editing EDI schemas

Biztalk handles the header and trailers of edifact messages for you.
UNA - generated by biztalk
UNB - generated by biztalk
UNH - included in schema
..  - included in schema
UNT - included in schema
UNZ - generated by biztalk

## Testing EDI schemas
Create a message with the format as described above. (Remove UNA, UNB and UNZ)
Right click the schema -> properties -> Validate Instance Input Type = Native, Input Instance Filename = path of message to test
Right click the schema -> Validate Instance

## Saving/reloading EDI schema created extra nodes.
The EDI messages keep everything in the root and then use references to use them where they belong.
Sometimes saving will delete the attribute that hides the referenced root nodes from the root.
Manually add it back:
add displayroot_reference="RootName" to the first <b:schemaInfo .. /> TODO: A screen shot with the line highlighted could probably communicate this more clearly.

## Writing XSLT schemas
If we want to concatenate all fields in a record into a single value it is tempting to do something like this:
<xsl:variable name="foo" select="record"/>
However this is dependent on the formatting of the input document.

if the input is:
<record><element1>1</element1><element2>2</element2></record>
then foo will be "12"

if the input is:
<record><element1>1</element1>
<element2>2</element2></record>
then foo will be "1\n2"

Instead you should do:
<xsl:variable name="foo" select="concat(record/element1, record/element2)"/>

## Pipeline CR LF or LF -> LF

If you have an issue with a file downloaded from client FTP where CR LF is sometimes LF and sometimes CR LF, and you need to strip out the CR.
In the BizTalk pipeline, set DecodeEnabled to true and DecodeValues to “0x0D-“
